# Dependencies — MEDIUM

Default severity: **MEDIUM** (a typosquat, an abandoned package with known
vulnerabilities, or a licence conflict is **HIGH**/**CRITICAL**). Apply only
when a manifest changed — `package.json`, `pyproject.toml`, `go.mod`,
`Cargo.toml`, `Gemfile`, … Lockfiles stay excluded from line-by-line review but
their diff is glanced at for surprises (a "patch" bump that pulled in dozens of
transitive changes).

Every dependency is a liability the team maintains forever; the review's job
is to make sure each one earns its place.

## Added dependency

- **Necessity.** Does the existing stack (or an already-present dependency)
  cover this? A one-function util rarely justifies a package; a date library
  when `Intl` does the job; a second HTTP client; a second state library.
- **Health & provenance.** Actively maintained; expected publisher (no
  typosquat — check the exact package name against the well-known one);
  reasonable download/usage; licence compatible with the project.
- **Weight (frontend).** Bundle impact — is it tree-shakeable, is there a
  lighter alternative, does it drag a polyfill or a whole icon set into the
  critical path? A dynamic import may be the right shape.
- **Version-range style** matches the repo's convention (`^`, `~`, exact).

## Bumped dependency

- **Major bump → read the migration notes**, not the version number. Semver is
  a promise the maintainer may not have kept; a "patch" can carry a behaviour
  change. Note known breaking changes relevant to the code that uses it.
- **Bulk "bump deps" commits** hide which package broke what — flag when a
  bump is mixed into a feature change, and prefer one dependency per change.
- Peer-dependency ranges still satisfied (React version, TypeScript version).

## Removed dependency

- `grep`/`rg` for leftover imports, config references, and type imports.
- Types packages (`@types/*`) removed alongside their runtime package.

## Lockfile

- Committed, generated by the repo's package manager (not hand-edited), and
  consistent with the manifest change (a manifest bump with no lockfile change
  — or the reverse — is a finding).

## What not to flag

- Routine minor/patch bumps with a clean lockfile diff.
- Style of the manifest file itself.
